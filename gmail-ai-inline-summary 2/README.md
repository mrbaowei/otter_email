# Email Otter

一个本地安装的 Chrome Manifest V3 插件。打开 Gmail、Outlook、Yahoo Mail、iCloud Mail、163邮箱、126邮箱或 QQ邮箱邮件后，它会自动读取当前页面已经加载的邮件正文，调用你自己的模型 API，并把中文摘要卡片直接插入正文上方。

当前版本：`0.7.20`

## 已实现

- 打开 Gmail、Outlook、Yahoo Mail、iCloud Mail、163邮箱、126邮箱或 QQ邮箱（包括新版 `wx.mail.qq.com`）邮件即自动总结，无需点击按钮或输入提示词
- 通过站点适配器识别当前邮箱，摘要、缓存和模型设置共用一套逻辑；当前支持 Gmail、Outlook、Yahoo、iCloud、163邮箱、126邮箱和 QQ邮箱
- 摘要卡片嵌入 Gmail 阅读区，而不是放在侧边栏
- 先快速生成一句结论、最多 3 条关键事实和首项待办；点击向下箭头后才按需生成详细总结
- 可在设置中开启“始终展开详细总结”，让详细总结自动生成并展开
- 所有已识别邮件的待办会汇总到右下角的彩色 Otter 悬浮球；点击待办会在新标签页打开对应邮件
- 悬浮列表可将待办标记完成或直接移除，两种操作都只清理本地待办，不会修改原邮件
- 简要摘要会一并生成 2–3 条可点击的跟进回复短句；明确无需回复时不会显示。点击短句后生成可编辑、可复制的回复草稿，不会自动发送
- 支持自定义 OpenAI Chat Completions 兼容格式、OpenAI 官方 Responses API、Google AI Studio Gemini API；每个服务商独立保存 Key、模型与 Endpoint
- 保留 DeepSeek 和 OpenRouter 兼容预设
- 默认强制输出简体中文，语言可自定义
- 按邮件内容生成签名并本地缓存；相同内容不会重复调用 API
- 邮件更新后自动重新识别
- 支持 Gmail 普通阅读和右侧分栏阅读布局
- 支持 Gmail、Outlook 的垃圾邮件阅读页；只读取页面已经显示的正文，不会显示被阻止内容、启用链接或移动邮件
- API Key 保存在本机 Chrome 扩展存储中
- 设置页底部提供默认折叠的 Token 用量记录表，按摘要请求记录输入、输出和合计 Token，并保留累计总量
- 提示词对邮件正文进行不可信输入隔离，降低提示注入风险

## 安装

1. 解压下载的 ZIP。
2. Chrome 地址栏打开 `chrome://extensions`。
3. 打开右上角“开发者模式”。
4. 点击“加载已解压的扩展程序”。
5. 选择解压后的 `gmail-ai-inline-summary 2` 文件夹。
6. 点击插件图标 →“模型与摘要设置”，填写自己的 API Key。
7. 刷新 Gmail，打开任意邮件。

## 默认配置

新安装默认使用 OpenAI 官方 Responses API：

- Endpoint：`https://api.openai.com/v1/responses`
- Model：`gpt-4.1-mini`

也可以切换到：

- 自定义 OpenAI 兼容：填写完整 Chat Completions Endpoint、模型与服务商 Key
- Google AI Studio：默认 `gemini-2.5-flash`，使用 AI Studio 创建的 Gemini API Key
- DeepSeek：默认 `deepseek-chat`
- OpenRouter：默认 `openai/gpt-4.1-mini`
- 本机 localhost/127.0.0.1 的 OpenAI 兼容接口；无鉴权时 API Key 可以留空

模型名称会随服务商调整。如果默认模型下线，在设置中改成账号当前可用的模型即可。

## 数据与隐私

- 插件没有开发者后端，也没有统计或埋点。
- 邮件正文只发送给你在设置中选择的模型 API。
- API Key 和摘要缓存保存在 `chrome.storage.local`。
- Token 用量记录也只保存在本机 `chrome.storage.local`，记录邮件主题、模型和 Token 数量，不保存邮件正文。
- Chrome 扩展本地存储不是密码保险箱；请给 API Key 设置合理限额，并尽量使用专用 Key。
- 使用自定义 API Endpoint 时，Chrome 会要求你单独授权该域名。

## 订阅与本机登录凭据

- Email Otter 不读取或复用本机 Codex、ChatGPT、Antigravity 等客户端的登录令牌、Cookie 或私有配置文件。
- ChatGPT/Codex 订阅不是 OpenAI Platform API Key；OpenAI 官方服务需要单独填写 Platform API Key。
- Google AI Studio 服务需要单独创建 Gemini API Key。Antigravity 订阅额度不作为 Gemini API Key 使用。
- 如果本机运行了用户明确配置的 OpenAI 兼容 HTTP 服务，可以通过“自定义 OpenAI 兼容格式”连接 localhost/127.0.0.1。

## 当前限制

### 其他邮箱的页面结构

Outlook、Yahoo、iCloud、163邮箱、QQ邮箱和 126邮箱通过当前网页 DOM 读取已打开邮件，不使用各家邮箱 API。各家网页的类名和布局可能随产品更新变化；如果打开邮件后没有出现摘要，需要记录页面和邮箱版本，再更新 `site-adapters.js` 中对应站点的选择器。当前版本优先支持阅读页，写信/草稿页不会主动摘要。

### 只能总结当前页面已经加载的内容

第一版通过邮箱页面 DOM 工作，不使用 Gmail、QQ邮箱、126/163邮箱、Yahoo、iCloud 或 Outlook OAuth/API。因此它能自动总结打开的邮件，但不会在后台预先读取整个收件箱。长线程中如果邮箱没有把早期折叠邮件正文加载进页面，摘要可能只包含已加载的部分。

后台预摘要整个收件箱需要第二阶段接入 Gmail API，包括：

- Google Cloud OAuth Client
- `gmail.readonly` 权限审核/授权
- 新邮件监听或定期增量同步
- 本地/服务端摘要队列

### 邮箱页面结构可能变化

这些邮箱没有为本插件提供稳定的邮件正文 DOM API。如果邮箱厂商修改页面结构，插件可能需要更新 `site-adapters.js` 中的选择器。

### AI 可能出错

摘要不能代替原文。付款、登录、交易、合同、法律、医疗、金额和截止日期必须核对邮件原文。恶意邮件也可能尝试提示注入；插件已做提示隔离，但无法保证所有模型都完全免疫。
